## 任务内容
搭建 Web 管理端地基：
- **登录页**：基于 admins 表的管理员登录
- **主布局**：侧边菜单 + 顶栏 + 面包屑 + 内容区
- **RBAC 权限框架**：roles / admin_roles 表，角色-权限映射，路由守卫与菜单过滤
- **品牌定制**：Element Plus 默认组件 + 品牌墨绿主色（pine-deep #2D4A43）定制
- **角色**：内容运营（建书/审核/举报/运营位/活动）、超级管理员（全权限+财务+权限分配）

## 结果
管理端可登录并看到菜单框架，菜单与操作按角色权限过滤。

## 角色与权限点（与 db seed 一致）
| 角色 code | 名称 | 关键权限 |
| --- | --- | --- |
| `super_admin` | 超级管理员 | `*` |
| `content_ops` | 内容运营 | 建书/分类/标签/审核/举报/运营位/活动 |
| `finance` | 财务运营 | 订单/流水/兑换码/会员 |
| `customer_service` | 客服 | 反馈/举报查看/用户查询 |

## API 对接说明
| 前端函数 | 后端端点 | 说明 |
| --- | --- | --- |
| `login()` | POST /api/admin/login | 用户名 + 密码登录，返回双令牌 + admin |
| `getProfile()` | GET /api/admin/profile | 当前管理员信息（需 Bearer） |
| 刷新 | POST /api/auth/refresh（拦截器自动） | 401 时换新令牌 |

> 说明：后端 `/api/admin/profile` 当前未返回角色字段。前端 RBAC 框架完整落地，登录默认授予 `super_admin`；dev 下登录页提供角色模拟下拉，可在不改后端的情况下验证不同角色的菜单/路由/指令过滤差异。后端打通 roles 接口后，`admin store.setRoles()` 接入即可切换为真实角色。
